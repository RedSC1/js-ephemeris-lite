# 日月食替换验证

## 当前生产实现（2026-09-06）

已接入现代全球与地方日月食 API，移除旧计算器和界线 API。运行：

```sh
node scripts/experiments/validate-modern-eclipses.mjs
```

旧基线由 `legacy-baseline.mjs` 从本地 `v1.0.0-beta.5` tag 解包到临时目录，
进程退出时清理；生产代码及 npm 包不携带旧日月食实现。

1900-01-01 至 2100-01-01 的公共区间 API，本机单轮完整结果耗时：

| API | beta.5 | 新实现 |
| --- | --- | --- |
| 日食搜索 | 4520 ms / 437 场 | 1236 ms / 452 场 |
| 月食搜索 | 4698 ms / 460 场 | 998 ms / 460 场 |

旧区间 API 在将朔序号转为浮点日期后再次取整时会重复前一朔，漏掉 15 场。
这 15 场均能由旧的单场查询确认；新枚举直接传递整数朔序号。
这一表不是等事件数微基准，也不是 C++ 二进制与 JS 运行速度比较。

已知 5 场日食类型差异来自所用日月半径约定，日期与半径对照见下方历史实验。
完整现代 API 还检查了 -6000–10000 年 800 个时间样本中的有限结果；抽样
不是整个年代范围不漏食的证明。C++ 影锥判别函数的 534 组生产代码对拍，
最大差 `2.88e-12`。未完成独立 DE441 全套食甚、地方接触和食带宽度真值验证。

以下记录各阶段实验，文中的“现版”“未接入生产”均指该阶段状态，不是以上
最终实现状态。原型与完整公共 API 的工作量不同，请勿混用计时。

## 第一阶段：月食接触求解实验

运行：

```sh
node scripts/experiments/benchmark-lunar-elements.mjs 1900 2100
```

输出 `/tmp/lunar-elements-result.json`，不会修改生产系数或求解器。

本实验借鉴 C++ `lunar_eclipse_search.cpp` 的五点三次拟合流程，保留
JS 的朔望初值、食甚迭代、二维角坐标和阴影半径。因此它比较的是局部接触
求解方法，不是完整 C++ 月食模型的移植，也不代表与 DE441 的绝对精度比较。

在食甚前后各六小时取五点，拟合位置和三个接触边界半径；中心点复用
食甚计算结果。按真实采样值确定区间，在多项式上二分求根；若拟合失去
括根条件，回到真实几何求根。没有有效区间则报错，不把失败伪装成无食。

脚本逐朔望比较类型及接触存在性，并对均匀抽取的事件使用原始 JS 几何
逐次求根作为接触阶段参考。该参考共用食甚与阴影模型，不能验证它们自身
的误差。计时包含预热和交替顺序的三轮运行，不包含直接求根参考计算。

交点预筛选单独运行：

```sh
node scripts/experiments/benchmark-lunar-filter.mjs
```

它比较原算法、预筛选加原算法、预筛选加三次拟合三组，输出
`/tmp/lunar-filter-result.json`。逐朔望检查 1900—2100 年附近区间，另在
-6000—10000 年间取 1600 个分层朔望样本；抽样未漏食不等于全区间无漏食证明。
筛选采用 C++ 中 Meeus 交点参数 F 与 23 度余量，尚未接入生产接口。

## 本机试验结果（2026-09-06）

Node.js v25.9.0，macOS arm64。以下为三轮耗时中位数。

| 搜索方案 | 2474 个朔望总耗时 |
| --- | --- |
| 原算法 | 4780.6 ms |
| 交点预筛选 + 原算法 | 1406.6 ms |
| 交点预筛选 + 三次拟合 | 1438.9 ms |

460 场月食（含半影）事件与接触存在性无差异；预筛选跳过 1843 个朔望，
未漏掉此样本中的事件。宽年代 1600 个朔望抽样包含 308 场月食，也未发现
预筛选漏食。

单独替换接触多项式，460 场事件耗时中位数从 1113.9 ms 变为 1147.6 ms，
慢约 3%。现代区间没有触发直接求根回退。

在 46 场分布抽样事件的 180 个接触上，相对于原始 JS 几何直接求根：

| 接触算法 | RMS | 最大误差 |
| --- | --- | --- |
| 原算法 | 0.0224 s | 0.2058 s |
| 三次拟合 | 0.00311 s | 0.02372 s |

这些是接触求解的内部一致性误差，并非相对于真实观测或 DE441 的总误差。
食甚保持现版路径，未在本轮评价。

主要搜索提速来自交点预筛选（本机约 3.4 倍），五点三次拟合提高接触求解
一致性但未提速。实验尚未移植 C++ 的三维阴影、食甚迭代、联合视位置或
地形月缘，不能作为完整 C++ 对 JS 的速度对比。生产替换前仍需极端年代、
擦边食及独立星历对拍。

## 日月食几何流程实验

```sh
node scripts/experiments/benchmark-eclipse-geometry.mjs 1900 2100
```

C++ 参考快照：`taiyin-ephemeris-public`，提交
`d87179310779b8577d0ccea6a9ee86346ed2182e`。

- 日食：Meeus 初值、九级步长的三维影轴食甚修正、圆形影锥与 WGS84
  扁地球相交、直接接触求根、中心食附近的全/环/混合分类。
- 月食：Meeus 初值、三维 Chauvenet 阴影、四轮上限的食甚修正、五点
  三次拟合接触求根。
- 日食额外测三小时采样、线性插值的物理修正窗口。在 J2000 轴下合并
  光行时与光行差位移，运行时重新计算几何位置和日期坐标变换。它保留
  C++ 的窗口思路，但没有复刻其分离修正项、矩阵插值和底层联合求值器。

两边共用 JS 的完整日月星历，关闭太阳引力偏折。实验使用圆形月缘，
不含 C++ 的 TLL1 地形；不含地方食、可见性、路径宽度、持续时间及地图。
日食当前食分仅计算中心食的视半径比，非中心食不伪造食分。没有接上
全部现有公共返回字段，因此本实验不能直接替换生产 API。

比较的是食类型、食甚、共同的全球接触时刻及可比较的食分；旧 API 还
计算额外输出，耗时不是逐字段工作量完全相同的纯求根微基准。

### 影锥几何与 C++ 对拍

从仓库根目录执行（C++ 仓库路径按需修改）：

```sh
c++ -std=c++17 -O2 \
  -I ../taiyin-ephemeris-public/include -I ../taiyin-ephemeris-public/src \
  scripts/experiments/solar-shadow-oracle.cpp \
  ../taiyin-ephemeris-public/src/runtime/eclipse/solar_shadow_geometry.cpp \
  ../taiyin-ephemeris-public/src/vector3.cpp \
  ../taiyin-ephemeris-public/src/angle.cpp -o /tmp/solar-shadow-oracle
node scripts/experiments/check-solar-shadow.mjs /tmp/solar-shadow-oracle
```

534 组输入的归一化相交判别量最大差 `1.7142e-12`。这验证了该几何函数
的移植，不等于完整食甚、接触与独立 DE441 真值完成对拍。

### 进一步实验结果

同一台机器与 JS 日月星历，1900—2100 年附近的 2474 个朔望。
三轮交替顺序计时中位数；比较前已用相同输入遍历算法。

| 方案 | 日食搜索（452 场） | 月食搜索（460 场） |
| --- | --- | --- |
| 现有 JS | 4736 ms | 4899 ms |
| 仅加交点筛选 | 1183 ms | 1461 ms |
| C++ 式直接几何/三维阴影流程 | 7301 ms | 1028 ms |
| 日食加修正窗口 | 2980 ms | — |

| 已知事件逐场计算 | 现版 | 几何实验版 | 日食修正窗口 |
| --- | --- | --- | --- |
| 452 场日食 | 851 ms | 6610 ms | 2553 ms |
| 460 场月食 | 1127 ms | 841 ms | — |

这不是本机 C++ 二进制与 JS 的跑分。C++ 的底层联合星历求值和矩阵窗口
仍与本实验不同；实验用 JS 星历检验求解流程在当前库中的表现。

现代区间事件存在性一致。月食食类型、接触存在性也一致，但食甚最大差
13.16 秒，接触最大差 36.34 秒；这包含三维阴影、求极值定义和半径模型
的变化，不能将新旧差值视作绝对精度。50 场抽样事件的 198 个接触，用
新模型的原始几何直接求根检查，三次拟合 RMS 为 0.00259 秒，最大
0.00724 秒。半影食中现版本影食分固定为零，实验模型可以为负，故原始
JSON 的全样本 `magnitudeDelta` 混有语义差异；应看验证文件中排除半影食
后的本影食分差（31 场 RMS 0.000264，最大 0.000365）。

日食食甚最大差 2.39 秒，共同接触最大差 112.62 秒。五场食类型差异
（1909-06-17、1927-01-03、1948-05-09、1966-05-20、2013-11-03）在实验版
采用现版本影月半径与太阳半径后均对齐。现版半影与本影采用不同月半径，
而默认实验使用 C++ almanac 单一月半径，不能直接据此判断分类准确性。
另有三场的旧 `centralBegin` 晚于 `centralEnd`，新几何认为影轴未穿过
地球，需单独核对非中心食的返回语义。

日食窗口相对于直接星历的接触差 RMS 0.00866 秒，最大 0.02628 秒。

宽年代 -6000—10000 年间每 20 年取一个朔望，共 800 个样本，现版含
151 场日食、158 场月食。原样采用 C++ 的 Meeus 日食初值与固定修正
步长，在此 JS 星历上有 8 场日食未找回；这些事件都通过交点筛选。
对应初值与 JS 精确合朔差约 17—24 小时，超出逐级收缩步长所能纠正的
总量。改用精确合朔初值后，这 8 场恢复。这反映了将初值和搜索范围接到
当前宽年代模型时需要重新验证，不能据此推断 C++ 所有运行配置的结果。
月食本轮宽年代抽样未发现事件缺失或分类差异。

原始结果保存在 `results/`。生产 API 未修改；完整替换仍需将半径模型、
非中心食语义、宽年代初值、地方食及原 API 的其他字段接齐，并使用独立
星历确认误差。当前证据支持继续推进月食；日食优先保留插值结构并加入
经过验证的搜索筛选，直接几何流程在 JS 上没有显示单场速度优势。

执行 `node scripts/experiments/diagnose-solar-seeds.mjs`，同时统一本影半径
常数并使用精确合朔种子后，800 个宽年代日食抽样中 151 场事件存在性及
食类型全部与现版对齐。该诊断路径的耗时未计入上面的原流程计时表。

## 新日食流程的局部多项式优化

`solar-polynomial.mjs` 使用精确合朔种子，对同一次事件共享日月赤道向量
的 Newton 插值多项式。影锥、扁地球、接触求根、分类仍使用新几何流程，
没有调用旧日食插值器或影锥算法。窗口外直接求值，不作无界外推。

`solar-cone-fast.mjs` 将影锥判别式按旋转后的二次型展开，预计算 24 个
粗搜索角度，避免每次搜索角度时创建、旋转两个向量。534 组输入相对于
先前已对拍 C++ 的向量版本，判别量最大差约 `2.8e-12`。

```sh
node scripts/experiments/benchmark-solar-polynomial.mjs 7
node scripts/experiments/benchmark-solar-polynomial.mjs 5
node scripts/experiments/validate-solar-polynomial.mjs
```

七点版在 452 场现代日食上与新直接几何版类型、接触存在性一致，食甚
最大差 0.0154 秒，接触最大差 0.0194 秒。这里直接几何版的接触根区间
终止阈值本身为 0.02 秒，不能将全部差值归于插值。

七点版三轮中位数：旧逐场 864 ms，新逐场 950 ms；旧逐朔望搜索
4740 ms，新搜索 1280 ms。没有事件需要在插值窗口外额外求值。

宽年代 800 个朔望抽样、151 场日食，七点版与同一精确初值的新直接几何
版不存在事件或分类差异，接触最大差 0.0191 秒。现代分布抽样的原始
向量最大插值误差约 1.14 米；直接几何接触残差除以接触函数斜率，对应
最大 0.00990 秒。未将这些内部几何一致性指标当作独立星历精度。

五点版同样通过 452 场现代事件的分类、接触存在性对比。三轮中位数：
旧逐场 878 ms，新逐场 820 ms（约快 6.5%）；旧搜索 4925 ms，新搜索
1257 ms（约 3.9 倍）。现代接触相对直接版最大差 0.0195 秒。

执行 `node scripts/experiments/validate-solar-polynomial.mjs 5`：宽年代
151 场事件无存在性、类型差异，接触最大差 0.0201 秒，无窗口外额外求值。
现代抽样直接几何接触残差对应最大 0.00995 秒。

因此新的日食几何流程可以通过共享局部多项式达到接近或略优于现版的
单场耗时；无需为性能而永久保留旧日食引擎。完整 API 替换尚未实施，
实验仍未接齐地方日食和所有旧界线接口。
